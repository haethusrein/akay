## Known limitations (prototype)

- **Phone numbers are not verified.** There is no SMS one-time code. Users are trusted to register their own mobile number, because SMS verification has a cost that a student prototype cannot cover. A person could register someone else's number.
- **Sign-in uses a hidden email.** Accounts are created as `<number>@akay.app` in Firebase email/password auth. There is no password-reset flow.
- **Responder verification is manual.** Verification codes are generated by an administrator in the Firebase console and handed to responders directly.
- **Security rules** live in `test_app/firestore.rules`. Deploy them with `firebase deploy --only firestore:rules` from `test_app/`, and do not edit them in the console.
